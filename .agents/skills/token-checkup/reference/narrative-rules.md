# 叙事约束：怎么读 facts.json 而不骗自己

> 这份文件不是风格指南，是**防翻车清单**。
> 它由一次真实审计中的 **9 个测量错误**提炼而成——8 个被自查拦下，
> 1 个逃过了两轮自查、最后被**使用者本人的异议**拦下。每一个当时都看起来像发现。
> 生成报告前必须完整读一遍。

---

## 三条铁律

### 铁律一：惊人发现默认视为测量错误

任何"哇"级别的结论，在用**独立方法**验证通过之前，一律当作测量错误处理。

验证不通过 → 不写进报告。
验证通过 → 把验证过程一并写出来（读者需要知道你查过）。

**为什么这条排第一：** 在原始审计里，9 个被推翻的"发现"**全部**比真相更耸动。这不是巧合——
真实世界很少那么整齐，所以**戏剧性本身就是可疑信号**。

**⚠ 讨喜的惊人发现更危险。** 第 9 个错误（「主动 compact 0 次」）逃过了两轮自查，
因为它耸动的方向是个好故事（"意外发现"很好讲）——戏剧性预警对坏消息灵，对好故事容易失灵。

> 自查：如果这个结论让我想立刻发出去，那它更需要先被证伪一次。
> **好故事和坏消息一样，都要先被证伪。**

### 铁律二：出处铁律

报告里出现的每一个数字，必须能指回两者之一：

1. `facts.json` 里某个字段（从数据算出来的）
2. **明确标注的选择**（"这是本工具默认值 / 你自己定的线，**不是行业标准**"）

两者都不是的数字，**不许出现**。

**反面教材：** 某次分析中，模型顺手写下"健康值应该在 80–150K"。这个数字没有任何出处，
但它随后被抄进脚本、抄进提示词、抄进 README、差点抄进对外的口播稿——
**每被继承一次就显得更权威一分**，最后险些以"业界公认"的身份对外发布。

> 自查：这个阈值/区间/基准是谁说的？答不上来就删掉，或改写成"我选的"。

### 铁律三：禁止用「结果的构成要素」去预测结果

算相关系数之前必须先问：**这个自变量是不是因变量的算术组成部分？**

是 → 相关性来自定义而非数据，必须换口径或直接放弃。

**必做的安慰剂检验：**
构造一个只含算术、零行为信息的假因变量，用同一个自变量去预测它。
**若安慰剂的 r 与真实 r 同量级，该相关系数作废。**

**反面教材：**
```
结论：「决定成本的不是活有多难（r=0.15），是每轮背多重的上下文（r=0.61）」

实测：真实   均上下文 → 每KB成本   r = +0.58
      安慰剂 均上下文 → 纯算术假成本 r = +0.62   ← 零信息，相关性反而更高

原因：成本 ≈ 轮次 × 上下文 × 单价，上下文本身就是成本的构成要素。
      而对照组「复杂度」含代码KB，代码KB 又在「每KB成本」的分母上，
      被机械地推向 0 —— 一个被推高，一个被推低，然后拿来对比。
      换成不含代码KB的「总成本」重算：复杂度 r 从 0.07 跳到 0.91，结论直接反转。
```

> 自查：换一个同样合理的口径，这个结论会不会反过来？会 → 它不是结论，是构造。

## 五条派生规则

### R1 区分「观察」与「推断」

写"我观察到 X"和"我认为 X 导致 Y"必须用不同措辞，且后者要标注混淆因素。

**范例（正确）：**
> 上下文 >250K 时，短回复的中位耗时是 <100K 的 3.14 倍。
> ⚠ 已控制输出长度；但仍无法排除"难任务同时导致上下文长和思考久"。

**范例（错误）：**
> 上下文越长，模型越慢——慢 1.97 倍。

### R2 不做横向对比，除非有真实基准

没有权威的行业基准就**不要凭空造一个**。所有判断默认是「你 vs 你自己」：

- 你的理论下限（每轮开新对话最少要付多少）
- 你自己的分布（P50 / P90——**必须先剔除程序化流量**）
- 你上一次体检的数字

**⚠ 拿「自己最省的项目」当参照前，必须核实流量性质。**
反面教材：曾把一个应用的程序化调用（会话中位 2 轮——程序天生如此）画成
「健康参照线」，还给它配了个被马拉松拉高的均值 9.7。程序的行为不能给人当标杆。

**图上要画参考线/参考带，必须满足下面两类锚点至少一类，并把推导写在图旁：**
1. **外部锚点**：官方公布值（如上下文窗口 200K / 258K）——可引用；
2. **内部锚点**：自身实测的分层（如受控延迟：≤100K 基线 3.0s、100–250K +60%、≥250K ×3.14）——可复跑。

两类锚点都没有的线，不许上图；只能作为「自定操作线」出现在文字里，并按铁律二标注。
分档要注明是「代价档位」而非「安全区」——除非实测存在拐点。

### R3 平均数必须检查是否混合了异质总体

合并前先问：这两组的分布是不是差很远？

**反面教材：** 某项目被判为"轮次最多却上下文最轻（158K）"，据此得出"多用子 agent 能省"。
实际是主对话（2,729 轮 @ 378K）与子 agent（5,953 轮 @ 57K）混算的平均数——
**主对话是全场最重的之一**。典型辛普森悖论。

> 自查：这个平均数背后是一个总体还是两个？分开算结论会变吗？

### R4 机制叙事必须匹配数据的异质性

"对话越拖越长"只适用于**上下文随轮次递增**的会话。
有些会话上下文从早期就冲高然后在高位锯齿（撞顶→自动压缩→再冲高），
斜率接近 0——**对它们"多开新对话"是无效建议**，问题在"每轮读进来的东西太重"。

> 生成建议前先看 `facts.json` 里每个项目的 `ctx_slope_per_turn` 和 `ctx_turn_corr`：
> - 斜率大、相关高 → **拖太长型**，建议换气
> - 斜率≈0 但均值高 → **每轮载重型**，建议减少单轮读入量

### R5 「独立验证」必须是不同数据通路；当事人异议是正式检验触发器

- **不同脚本、同一假设、同一字段，不算独立验证**——那是同一个错误跑了两遍。
  独立 = 换一条数据通路（例：usage 统计 vs 权威元数据字段 vs 使用者的记忆）。
- **有权威字段就不许用字符串猜。** 判定一件事之前先问：日志里有没有直接记录它的字段？
- **使用者说"这不对，我记得不是这样"时，必须当场用独立通路核查**，不许用数据压人。

**反面教材：** 「41,633 轮里主动 compact 0 次」——判定手动/自动用的是
"摘要含 `ran out of context` → 自动"的字符串猜测，而手动与自动的续接摘要**都**含这句话。
权威字段 `compactMetadata.trigger` 实测：**手动 16 次 / 自动 5 次**，方向完全相反。
该结论通过了两轮自查和一次"端到端验证"（基准是审计自己的数字——循环验证），
最后是**使用者本人的记忆**把它拦下的。

## 禁语表

| ❌ 不许写 | ✅ 改成 |
|---|---|
| 「业界公认 X」 | 「我自己定的 X，不是行业标准」 |
| 「86% 的钱是浪费」 | 「重读是架构必然；刨去下限，剩余部分才是行为造成的」 |
| 「健康区间是 A–B」 | 「你的分布是 P50/P90/P99；线由你自己定」 |
| 「X 之后开始退化」 | 「从 X 起每档递增，无拐点」 |
| 「r 高 → X 决定 Y」 | 先跑安慰剂检验，过不了就不写 |
| 「已蒸发 / 已丢失」 | 「原路径不存在」——必须逐个核实新位置 |
| 「省下 X%」 | 「模拟上界 X%，未计入换气导致的返工」 |

## 已证伪结论清单（不许再出现）

来自一次完整审计，全部经实测推翻：

| 说法 | 实测 |
|---|---|
| 「一开场就背着很重的东西」 | 地基中位 28.5K，无一超 50K |
| 「配置文件太长拖累上下文」 | 占 0.7% |
| 「compact 用太多了」 | 全量仅 21 次，不多。⚠ 原证据「全自动/主动 0 次」本身是测量错误（实为 16 手动/5 自动，见 R5）|
| 「健康值 80–150K」 | 无出处；实测无拐点 |
| 「子 agent 让某项目更省」 | 辛普森悖论，主对话实为最重 |
| 「工作散落临时目录是最大盲区」 | 临时路径仅 0.2%，约 76% 在 git 里 |
| 「决定成本的是上下文不是难度」 | 相关系数被构造污染，换口径即反转 |

## 九次测量错误（方法论教训）

| 假发现 | 真相 | 错在哪 |
|---|---|---|
| 缓存在反复失效 | 命中率 97% | 假设未验证就当结论 |
| 用 `gitBranch` 判断版本控制 | 该字段 60% 是兜底值 `HEAD` | 没核实字段语义 |
| 33.9% 的投入已蒸发 | 目录只是被移动了 | 把"路径不存在"等同于"工作丢了" |
| 换气到 100K 能省 57% | 模拟里换气是免费的 | 模型缺陷冒充发现 |
| 85% 的开场"一次说清" | 测的是注入的 skill 定义与应用人设 | 没区分人的输入与系统注入 |
| 打完补丁脚本"跑通了" | `NameError` 被 `except: pass` 吞掉，输出全零 | 只看退出码，没验证输出值 |
| 上下文让响应慢 1.97 倍 | 控制输出后：短回复 3.14×，长回复反转 0.55× | 没控制混淆变量 |
| 「上下文决定成本 r=0.61」 | 算术恒等式；安慰剂 r=+0.62 更高 | 用结果的构成要素预测结果 |
| **「主动 compact 0 次」** | 权威字段实测：**手动 16 / 自动 5** | 有权威字段却用字符串猜；发现讨喜而逃过自查；用户异议才拦下 |

**共同点：九个全部比真相更耸动。前八个被自查拦下；第九个因为是"好故事"逃过了自查，**
**由使用者本人的记忆拦下——所以当事人异议是正式检验渠道（R5）。**

## 生成报告前的自查清单

逐条打勾，未通过不得输出：

- [ ] 每个数字都能指回 `facts.json` 字段或标注为「选择」
- [ ] 每个关键结论至少有一条**不同数据通路**的旁证；有权威字段的没用字符串猜
- [ ] 讨喜的"意外发现"和坏消息一样先被证伪过
- [ ] 所有相关系数都跑过安慰剂检验
- [ ] 所有平均数都检查过是否混合异质总体
- [ ] 所有因果表述都标注了混淆因素
- [ ] 没有出现禁语表里的说法
- [ ] 没有引用已证伪清单里的结论
- [ ] 建议区分了「拖太长型」和「每轮载重型」
- [ ] 局限声明单独成节，不藏在脚注里
- [ ] 如果某个问题数据回答不了，**明确写出"回答不了"**，而不是给一个弱答案
