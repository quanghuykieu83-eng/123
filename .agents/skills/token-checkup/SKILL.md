# Token 体检

给使用者的 AI 协作习惯做一次成本与效率审计。**只读本机日志，不上传任何内容。**

## 开始之前：必读

**先完整读 `reference/narrative-rules.md`，再做任何事。**

那份文件不是风格指南，是防翻车清单——它由一次真实审计中的 9 个测量错误提炼而成
（8 个被自查拦下，1 个逃过两轮自查、最后被使用者本人的异议拦下），
每一个当时都看起来像发现。跳过它，你会重犯同样的错，而且**看不出来自己错了**。

三条铁律的短版（细则见原文）：

1. **惊人发现默认视为测量错误**，直到用**不同数据通路**验证通过（不同脚本同一假设不算）。
   讨喜的好故事和坏消息一样要先被证伪。
2. **每个数字必须能指回**：facts.json 的字段，或明确标注的"这是选择，不是标准"。
3. **禁止用「结果的构成要素」预测结果**——算相关系数前先跑安慰剂检验。

另：**使用者说"这数字和我记忆不符"时，当场用独立通路核查**——那是免费的检验信号，
上一次它拦下了自查漏掉的错误。

## 流程

### 第 1 步：扫描

```bash
python3 scripts/scan.py -o facts.json
```

单次遍历，几秒到几十秒（取决于日志量）。会打印一份摘要。

- 限定时间窗：`AUDIT_SINCE=2026-01-01 AUDIT_UNTIL=2026-06-30 python3 scripts/scan.py`
- 未检出 `~/.codex/sessions` 时，跨工具章节自动不出现——**不要输出空表格**

### 第 2 步：判断这是第几次

检查 `history.jsonl` 是否存在且非空：

- **不存在 → 全量版**（首次体检，走第 3 步）
- **存在 → 体检版**（走第 4 步）

用户明确要求"出完整报告"时，即使有历史也走全量版。

### 第 3 步（首次）：全量版

1. 读 `facts.json`。**逐字段读，不要凭印象写。**
2. 按 `narrative-rules.md` 的自查清单逐条过。
3. **和使用者确认那条线**——这一步不能省：

   > 你的上下文分布是：P50 xxx、P90 xxx、P99 xxx。
   > 目前没有任何权威标准说明"多少算健康"，实测也不存在拐点（只有连续递增的代价）。
   > 所以这条线得你自己定。建议从 P50 往下砍 30% 起步，你想定在多少？

   拿到答案后写入 `config.json`，并询问是否要据此更新状态栏。

4. 生成报告：
   ```bash
   python3 scripts/render_report.py facts.json -o "Token体检报告.html"
   ```
5. 追加基线：
   ```bash
   python3 scripts/append_history.py facts.json
   ```

### 第 4 步（复检）：体检版

1. 读 `facts.json` 与 `history.jsonl`。
2. 生成趋势对比（一页纸，不是 14 张图）：
   ```bash
   python3 scripts/render_checkup.py facts.json history.jsonl -o "Token体检_趋势.html"
   ```
3. 口头汇报时**只讲变化**，不要重述上次的结论：

   > 平均每轮上下文 243K → 178K（↓27%）
   > 主动 compact 0 → 12 次
   > ⚠ 新退步：「其他」项目占比 8% → 31%

4. 追加基线。
5. 用户想看细节时才生成全量版。

## 给建议时：先分类型，再开药方

`facts.json` 里每个项目都带 `growth_type`，**它决定给什么建议**：

| growth_type | 含义 | 有效建议 | 无效建议 |
|---|---|---|---|
| `拖太长型` | 上下文随轮次稳定增长 | 换气：开新对话 / compact | — |
| `每轮载重型` | 上下文高但不随轮次增长 | 减少单轮读入量：给精确路径、别整目录灌 | ❌ 换气（对它无效） |
| `null` | 判定不足 | 只陈述数字，不给建议 | — |

**把两者混为一谈会给出无效建议。**曾有一次分析对一个"每轮载重型"项目建议"多开新对话"，
而那个项目的上下文斜率其实接近 0——建议再正确也不会有任何效果。

## 常见问题的正确答法

| 用户问 | 怎么答 |
|---|---|
| "我这样算正常吗？" | 没有行业基准，我不编。只能跟你自己比：你的分布 / 你最省的项目 / 你上次的数字。 |
| "多少 token 该 compact？" | 实测无拐点，只有连续代价。这是取舍题不是知识题，线由你定。 |
| "我进步了吗？" | 需要至少 3 次体检才谈得上趋势；且要注意期间换过项目会混淆。 |
| "能省多少钱？" | 订阅制下账单不变。收益是更快、更不健忘、峰值不擦线。 |
| "我的 prompt 写得好吗？" | 只有"开场消息长度"是干净指标。返工率和纠正率都混着任务难度，只能看自身趋势。 |

## 产出物

| 文件 | 说明 |
|---|---|
| `facts.json` | 全部测量结果。**唯一的事实来源**，报告里每个数字都要能指回它 |
| `Token体检报告.html` | 全量版（首次/年度） |
| `Token体检_趋势.html` | 体检版（日常） |
| `history.jsonl` | 基线历史，每次追加一行 |
| `config.json` | 使用者自定的线 |

## 隐私

- **全部在本机运行，不发送任何数据。**
- `facts.json` 含项目目录名与统计量，**不含对话内容**。
- 分享报告前请自查：项目名可能泄露工作内容。
- 生成的报告默认不发布。使用者要求发布时再另行确认。
